## Contributions

- Created this controlled-change record and attempted a read-only SSH preflight using the system OpenSSH client.
- The board initially rejected the current Windows SSH keys. After the user supplied the existing `ubuntu` account credential out of band, authenticated SSH and `sudo` were verified successfully; the secret is not recorded here.
- Confirmed the board is Ubuntu 22.04.4 and `eth0` is `[private_ip]/24`. Samba was not installed and no listener existed on 139/445.
- Started `apt-get install samba`; apt identified 21 new and 3 upgraded packages (17.9 MB download, 68.9 MB installed footprint) but downloaded none because DNS resolution for `ports.ubuntu.com` failed. No Samba package, configuration, account, or firewall state was changed.
- At the user's direction, downloaded the matching Jammy arm64 dependency set from the local PC after resolving it against a copied KV260 `dpkg` status database. The offline bundle contains 25 `.deb` files; its gzip-tar SHA-256 was verified on the board before extraction.
- `apt-get --no-download` did not accept the extracted local package paths as archives, so it made no system change. Corrected by using the complete dependency set with `sudo dpkg -i`; installation completed, including Samba 2:4.15.13+dfsg-0ubuntu1.13 and four prerequisite library upgrades. Package installer `testparm` validation passed for the default Samba configuration.
- After user confirmation, created the Samba account `ubuntu` using the confirmed password (value not recorded), backed up the original board configuration as `/etc/samba/smb.conf.before-kv260-root-share`, and configured share `[root]` for `/root`. The share requires `ubuntu`, is read/write, and applies `force user = root` so authenticated uploads can modify the root-owned path.
- Applied the user-approved network bounds: `interfaces = lo eth0`, `bind interfaces only = yes`, `hosts allow = 127.0.0.1 192.168.10.`, and SMB2 minimum. Enabled and started `smbd`.

## Decisions and Adoption

- Adopted: authenticated SMB share `\\[private_ip]\root`, backed by `/root`, is limited to the local direct-link network and uses the `ubuntu` Samba account. The user explicitly approved reuse of the current Ubuntu password as the Samba password.

## Commands and Tools

- System OpenSSH/SCP interactive sessions, `sudo -v`, `dpkg-query`, `ip -brief address show eth0`, `ss -ltn`, `sudo apt-get install -y samba`, local Jammy arm64 metadata/dependency resolution, SHA-256 validation, and `sudo dpkg -i ./debs/*.deb`.
- Board configuration: backup `smb.conf`, add global binding/host/protocol restrictions, append `[root]`, `testparm`, `smbpasswd -a ubuntu`, `systemctl enable --now smbd`, `systemctl restart smbd`, and listener inspection. Windows validation: `Test-NetConnection [private_ip] -Port 445`.

## Validation and Evidence

- Authenticated `ubuntu` SSH and sudo access succeeded.
- Before install attempt: `samba` status `unknown ok not-installed`; TCP 139/445 listener table empty.
- Installation attempt failed solely with repeated `Temporary failure resolving 'ports.ubuntu.com'`; apt reported `Unable to fetch some archives`. No claimed Samba validation exists.
- Offline installation verification: package configuration reached `Setting up samba`; installer ran `testparm` and reported `Loaded services file OK`. A `samba-ad-dc.service` preset warning is expected for standalone Samba and does not affect `smbd` file sharing.
- Final board validation: `testparm` reports `Loaded services file OK`; `[root]` resolves to `/root`, `valid users = ubuntu`, and `force user = root`. `smbd` reports `active` and listens only on `127.0.0.1:445`, `[private_ip]:445`, and IPv6 loopback. The direct remote listener is therefore correctly bound to the direct-link IP, not every network interface.
- Final Windows validation: `Test-NetConnection [private_ip] -Port 445` returned `TcpTestSucceeded=True`. Full Explorer credential/login transfer was not automated; user must perform the first UNC login.

## Errors and Corrections

- The sandbox-provided `ssh` command is a deny wrapper, so the installed system OpenSSH client was used. Key-only login was rejected; the user then authorized password authentication.
- The board's direct Ethernet setup has no usable Internet/DNS path, so the package-install prerequisite cannot proceed. This is a connectivity/package-delivery blocker, not a Samba configuration failure.
- Local package cache on the Windows-mounted WSL filesystem could not reliably rename downloaded archives. Corrected by downloading to WSL `/tmp` and copying the completed bundle to the workspace before SCP transfer.
- Board clock is substantially behind the Windows host, which produced harmless future-timestamp warnings during tar extraction; archive SHA-256 matched before extraction.
- Initial include design placed a share definition inside `[global]`, causing downstream global parameters to be interpreted in a service section. Detected immediately through `testparm`; restored `smb.conf` from the pre-change backup and re-applied global restrictions in `[global]`, then appended `[root]` at EOF. Final `testparm` is clean.
- The Ubuntu default `map to guest = bad user` appeared after the first inserted `Never` setting and overrode it. Replaced the default value and restarted `smbd`; `guest ok = no` remains explicit for the root share.
