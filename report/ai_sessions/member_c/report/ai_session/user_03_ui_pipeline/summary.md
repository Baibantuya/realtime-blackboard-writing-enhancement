## 问题和输入

用户要求先将UI接入PS入口，把板面识别限为2Hz而保持画面刷新独立；随后接入底栏/历史页。一次中间实现改为单帧调度，用户明确质疑吞吐损失，要求恢复多阶段流水，并确定记录应保存当前模式对应画面。

## 结果与限制

早期2Hz候选回放约8.0116秒：16次识别、208次显示提交、最短识别间隔约0.5174秒，约25.9623次/秒提交。只说明显示未被限到2Hz；不是KV260摄像头/DRM显示FPS，也不是神经网络手势推理频率。

最终流水候选已有96项软件回归，涵盖三阶段重叠、模式路由、记录不含UI及历史浏览；本轮98个源码哈希与该回执匹配。中间98项与最终96项是不同测试集合，不能解释为倒退或凭数量等同覆盖。

WSLg回放记录477帧、13次截图、保存模式顺序[2,0,1]，但window_keys为空，说明该组是脚本驱动状态回放；不能称作真实键盘操作验证。U01的65项真实X11操作也不能拿来验证这个新按键映射。

当前最多32个运行内版面，没有磁盘持久化；截图虽然选择“深度增强”，背景仍是回放原视频，因为各路使用硬件替身，没有PL增强。这张图只支持分组/文案/布局，不支持实际增强效果。ARM构建、真实采集显示和板端吞吐仍未验证。
