# 赛题要求核对（依据本地提供版本）

来源为用户提供的 AMD 赛题 PDF 第 3.3 节，重点核对 PDF 文件页 23–25（印刷页 20–22）；[文字摘录](sources/rules/amd_section_3_3.txt)、[文件页24](sources/rules/amd-24.png)、[文件页25](sources/rules/amd-25.png)。本次核对的是本地版本，不代表已查询提交平台的最新补充通知。

| 条款 | 官方内容的整理摘要 | 本工作区对应及缺口 |
| --- | --- | --- |
| 3.3.3.1 | 保留提示词、模型回答、可见纠错轨迹，整理可复用技能。 | 本人六案有部分真实可见消息；队友仅资料摘要，不能替代原文。隐藏思维链不属于所需材料。 |
| 3.3.5.2 | skill/ 包含 README.md；写明适用范围、用法、失效条件、已验证效果和来自哪些失败或观察；可由提示词流程、模板、校验脚本、踩坑清单等构成。 | 两个 Skill 草稿已给出流程与来源；本次未做跨任务迁移试用，不声称已稳定泛化。 |
| 3.3.5.2、3.3.2 | 通用 PYNQ Skill 有单独加分条件。 | 当前两项草稿不是已验证的通用 PYNQ Skill，不自动主张该加分。 |
| 3.3.5.3 | 设计报告应说明协作过程、智能体工作流（如有）、技能提炼及验证边界。 | 本轮单代理；无新增多代理工作流。旧会话若提到其他机制，仅按实际证据归档。当前 LaTeX 不改动。 |
| 3.3.5.4 | 提供推荐目录，采用其他结构应给目录对照；文件与目录名称要求纯英文并限制字符。 | 根 readme 给目录对照；工作区与原项目的中文根路径不是最终提交结构。官方示例中的 README.md 保留。 |
| 3.3.5.5 | 大模型协作与技能包合计占 15/100。 | 不能把 15 分仅理解为聊天数量，或提前预测得分。 |

“3～5 个案例”“每案 1～3 页”是前期组织建议，**不是该 PDF 的固定要求**。本轮保留六个本人案例，便于按证据和篇幅再筛选；队友六个条目是候选导读，不代表全部提交。

工具版本建议为 2026.1 或 2025.2；队友 A 的早期记录使用 Vivado/xsim 2022.2，需保留事实并补充版本选择与复现说明，不能静默改写成推荐版本。平台上传项、大小、是否要求完整聊天、匿名细则和后续通知仍待核对。
