## 3. 最新数据流：Q 读取 A，不读取 B

```text
IMX219 → CSI/ISP → 相机帧 → PL Rectify → A：校正图
                                         ├→ PL 冻结 Restore → B：辅助恢复图
                                         ├→ PS Content.prepare（A 的 320×180 采样）
                                         │                 ↓
                                         │   Content.refine（同帧 B 采样）
                                         │                 ↓
                                         │            120×68 元数据
                                         ↓                 ↓
                                   PL Scene Q ← 旧 Canvas
                                         ↓
                                新 Canvas＋最终 RGB565
                                         ↓
                                 DRM / DP 显示与 UI
```

关键变化：最终 Q 为 `board_scene_quantize`，不是此前的 `board_quantize_rgb`。Q 使用 A 原始校正像素、PS 场景元数据和持久 Canvas；B 仅作为 PS 场景细化的同帧辅助证据。

调度器保持最多三对 A/B 的所有权。A 准备任务与 Restore 重叠；Restore 完成后才能用对应 B 完成细化。Q 按接纳顺序消费内容结果，完成后才释放 A/B 对，因此存在真实的同帧依赖，不是所有阶段都能任意异步。

内容结果必须匹配 capture、sequence、board、history、photometry 身份。默认在 Restore 完成后给内容结果 80 ms 等待预算；超时/失效则 Q 执行 HOLD 并计数，不让内容工作进程无限阻塞视频。内容包另有从捕获时间计算的有效期，不能把 80 ms 当作整链端到端延迟保证。

### Canvas 与元数据

- Q ABI：`0x57425321`；实际寄存器从匹配 HWH/IP-XACT 解析，不能沿用旧 Q 偏移。
- Canvas 每像素 4 bit：低 3 bit 为颜色标签，高 1 bit 为待确认擦除。0 板面、1 中性笔迹输出黑色、2 红、3 蓝、4 绿、7 未知。
- 两份 ping-pong Canvas，每份 1080p 为 1,036,800 字节，合计约 2.07 MB；不是两份完整 RGB565 背景。
- 每个 16×16 块有一个 uint32 元数据，1080p 共 8,160 项、32,640 字节，包含板面颜色与 VISIBLE/INITIALIZE/SURFACE_VALID/OCCLUDED/REVEAL 标志。
- 正常路径仍扫描全帧 A、读写 Canvas 并输出完整图像，不是已实现的稀疏像素调度。
- HOLD 路径不读 A 和元数据，读取旧 Canvas 输出画面，并清除待擦除位；仍读写 Canvas 和整帧显示数据。因此 HOLD 不是“新增内容”，也不是零成本。

当前 `SceneTracker` 主要使用传统图像差分、形态学、连通域、材质参考和可见性状态；其中 object_id 不是神经网络识别出的手身份。

## 4. 几何、曝光与内容身份分离

### 几何

- 几何进程接收自己拥有的 320×180 RGB565 小图，不跨进程持有相机 CMA；默认采样间隔 0.5 s，仍为 2 Hz。
- 状态区分 SEARCH、CONFIRM、TRACK、OCCLUDED、UNOBSERVABLE。局部人物遮挡不直接等同板面出画；完全遮挡且背景证据不足时明确表示不可观测。
- r4 的 2px 门槛按原相机像素、四角最大位移、相对最后已发布矩阵计算。慢移可累计，不是每帧位移阈值，也不是小图 2px。
- 矩阵版本与 board epoch 分离。普通相机移动保持固定输出板面坐标和 Canvas，下一次空闲 Rectify 启动采用新矩阵；在途帧保留自己的 transform，不全流水清空。
- 日志分 measured、applied、completed 和 PL echo，比较硬件回读必须使用同一已完成帧，不能将最新启动矩阵与旧完成回读混比。

### 曝光

- 持续自动曝光已接入独立 SensorService；采样提交上限约 4 Hz，控制行为由曝光模块决定，不能直接称每秒必写 4 次寄存器。
- 分区测光目标 80、容差 ±6；白平衡保持既有固定设置。
- 写曝光/增益前先更新 photometry 版本，并撤销稳定准入；过渡期限制内容提交，但不停止相机采集。
- 只控制全局曝光/增益，没有语义人物测光排除，不能保证消除所有局部反光。
- 交付记录出现过 `ae_limited=true`，暗部细线和曝光极限下的画质仍待现场验收，不能因此退回旧固定曝光。

### 初始化与重置

- 默认启动依据操作者“初始无人”的假设自动建立内容参考；这不是模型已经确认无人。
- F7 手动重置：停止准入、排空在途 DMA、重建参考/Canvas。F6 仍是保存当前画面，二者不同。
- 自动初始化的 RECTIFIED PREVIEW 过渡页已移除；真正找板时的引导画面保留。
