# 案例 02：恢复算法修复中的错误结论纠正与证据收敛

## 1. 案例信息

- 日期：2026-10-01
- AI：OpenAI Codex
- 主题：保留论文约束的黑板遮挡恢复、HLS/RTL 一致性和真实视频验证
- 源记录：[`2026-10-01-003-restoration-repair-test.md`](../../../member_b/shared_records/2026-10-01-003-restoration-repair-test.md)
- 记录状态：局部实现和测试完成；完整场景恢复未接受

## 2. 问题背景

恢复算法需要同时处理遮挡、细笔迹、历史背景和相机运动。只看缩略图容易把“局部变白”误认为“新笔迹被保留”，因此任务要求保留原始基线，分开验证算术一致性、真实视频效果和完整硬件接口。

## 3. 对话要点

以下内容根据内部会话摘要重建，**不是逐字聊天记录**。

### 用户任务

在不改变块采样、差分、计时器、空间传播和历史组合基本约束的情况下，实现受保护的恢复候选，并用真实视频、原生 C、Vitis HLS/RTL 和像素级检查验证。

### AI 贡献摘要

1. 建立 baseline/candidate 并行路径，加入数值 oracle、真实视频比较和视觉检查。
2. 逐轮分析新写入、皮肤污染、历史模糊和相机漂移，把每个失败保留下来。
3. 将 HLS C、NumPy 标量结果、RTL 输出和视频像素结果分层，不把其中一层的通过扩大成整机通过。
4. 最终加入清初始化、稀疏中性像素保护和 ORB/LK/RANSAC 板面配准，用于修复已观察到的板端漂移造成的模糊。

## 4. 团队决定与采用

- V7 对供应视频中的书写保留效果被采用为候选改进。
- “完整场景教师移除”不接受，因为历史污染和残留斑点仍然存在。
- 原始交付和媒体保持不变；硬件视频接口、整帧恢复 IP、路由时序和上板性能不被本次局部测试冒充。

## 5. 量化验证

- 处理 6067 帧，完成 445,560,480 个实际 HLS C++/NumPy 标量比较，0 mismatch。
- 不变核心的 C/综合/RTL directed 测试通过；独立 AXI 输出比较 153,106 个值，0 mismatch。
- 21 个 directed/random native properties 通过，包含邻域保护、保存/重新遮挡、全局冻结和配准测试。
- 199 s 局部裁剪中，886/886 条亮笔画出现在正确显示位置；保存背景 886/886 在 2 px 内，795/886 达到精确位置。
- 没有完整场景准确率声明；板端 IP、全 PL compositor、路由时序和 1080p30 性能均未执行。

## 6. 失败与纠正链

1. 初始缩略图判断“新笔迹被保留”错误；全分辨率裁剪显示候选版本仅 0/886 个亮笔画样本保留，而原始 W1 为 369/886。该结论被撤回。
2. V2 的阈值放宽后出现教师边缘污染，拒绝 whole-block fine release。
3. V5 虽然恢复了 886/886 个亮笔画，却引入皮肤颜色污染，被拒绝。
4. V6 的中性颜色限制仍导致板端笔迹模糊；进一步分析发现 40 s 和 63 s 相机漂移约 15 px/21 px，V7 加入板面配准。

## 7. 结果边界

- 通过的是局部算术、HLS/RTL 一致性和供应视频上的有界视觉证据。
- 不能据此声称所有衣服颜色、密集文字、相机运动或其他视频都能恢复。
- 当前恢复核心输出的是中间状态；完整 RGB 帧恢复、硬件接口和系统性能仍需独立工程验证。
