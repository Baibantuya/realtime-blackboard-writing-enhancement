# 提示词工作流 01: 算法描述 -> 软硬件边界划分推导

## 1. 适用场景
- 队伍拿到一个全新的算法（如图像滤波、特征提取、物理信号检测、音频编解码），需要科学地决定哪些模块放入 PL（FPGA 硬件流水线），哪些模块留在 PS（ARM / Python）。

## 2. 提示词模板 (Prompt Template)

```markdown
你是一位资深的 AMD FPGA 与嵌入式软硬件协同架构专家。
我正在使用 AMD PYNQ 平台（目标器件：<填写器件型号，如 Zynq UltraScale+ xck26 / Zynq-7020>）实现以下算法系统：

【算法功能描述与处理流程】：
<详细粘贴算法的数学公式、C/Python原型代码或流程步骤>

【输入输出规格与性能指标要求】：
- 输入数据吞吐与格式：<如 1080p RGB 视频流，30 FPS，每像素 2 字节>
- 单帧总时间预算 (Time Budget)：<如 33.3ms>
- 物理 DDR 带宽限制：<如 64-bit DDR4 @ 1200MHz，实测可用带宽约 8 GB/s>
- PS 处理器算力：<如 4 核 ARM Cortex-A53 @ 1.33GHz>

请按照以下结构，为我进行严谨的软硬件划分（HW/SW Partitioning）推导：

1. **算力与访存定量分析**：
   - 计算该算法每秒所需的乘加操作数（GOPS）与物理内存读写带宽需求（GB/s）；
   - 评估纯 PS 软件实现时，ARM Cortex-A53 单帧预计耗时与最大理论帧率。
2. **瓶颈识别与软硬件划分建议**：
   - 哪些环节属于“计算密集型、高度规整、像素级流式数据”？（划归 PL 硬件加速，并说明推荐的硬件结构：如滑动窗口 LineBuffer、纯流水线或多核并行）；
   - 哪些环节属于“控制密集型、复杂分支判断、低频全局状态更新”？（留在 PS 端处理，并评估 Python/C 运行开销）。
3. **软硬件接口与数据流契约设计**：
   - 定义 PS 与 PL 交互的拓扑结构（AXI4-Stream 直通 vs AXI4-MM DDR 乒乓共享内存）；
   - 定义 PL 核心的 AXI-Lite 控制寄存器映射草案（包含 64 位指针拆分与状态握手）；
   - 给出防止内存带宽竞争与缓存一致性穿透的防护策略。
```

## 3. 典型应用范例与产出效果
- **在白板项目中的实际应用**：早期将整帧仿射变换矫正、局部自适应阈值与多重历史时域融合划归 PL（200MHz 纯流水线，单帧耗时仅 15ms），而将四角透视拟合、全局光流追踪与页面擦除检测留在 PS 端（单帧 5ms），成功在 33.3ms 内完成闭环，取得 30 FPS 吞吐。
