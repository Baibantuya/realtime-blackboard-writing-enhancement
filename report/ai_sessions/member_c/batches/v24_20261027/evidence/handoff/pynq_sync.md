## 3. 必须更新的接口和运行说明

- 配置：`S/board/runtime/config/deployment.json`，schema 2，`V24-PS-SLIM-20261026`，ABI `0x57425321`，硬件身份 `V24-200MHz`。该名字中的频率不代表时序通过。
- 入口：`app/main.py --runtime <runtime>`，内部仍是多阶段流水。软件拆到 `app/`、`drivers/`、`ui/`；硬件在 `hardware/`。Python 配置路径 `/usr/local/share/pynq-venv/bin/python3`，实际版本仍需板端导出。
- 启停包装：`run.sh` 无参数仍默认 `deploy`，先由系统 `/usr/bin/python3` 调 `app/manage.py`，再使用配置的 PYNQ Python 启动主程序。`check` 分支会向 `/tmp` 复制硬件文件，加载器还会创建元数据副本、清理失效的 PYNQ 全局状态；“不下载 FPGA”不等于完全只读。离线材料核验应直接解析文件，不执行 `run.sh`。
- 数据：运行目录旁 `<runtime-name>.data/`，可由 `WB_DATA_DIR` 覆盖。全帧捕获请求在 `<data-dir>/capture_full.request`，几何请求在 `<data-dir>/geometry/capture.request`。
- 手动 F6 按当前模式保存；自动留页保存深度增强 Q 图；32 页运行内存。诊断捕获写盘与历史页断电保存是两个机制。
- 缓冲与调度：最多 3 对 A/B，Q 完成后释放；PS 工作者持有自己的缩图副本。几何分析 2 Hz 与显示独立，不改成单帧调度。
- Q 输入是 A＋120×68 区域元数据＋旧 Canvas，B 辅助 PS 同帧分析；元数据 8,160×4 byte，Canvas 4 bit/像素。说明、检查器和参考数据必须按当前接口核对。
- 迁移后必须复核 HWH 中 IP 名称、基址、范围、寄存器偏移、指针宽度、时钟、中断及复位。当前 HLS 量化端 m_axi_addr64=false、恢复端 true；不要统一假设所有地址都只写低 32 位或都使用双寄存器。

## 5. 六组新 Skill 与既有离线检查器如何衔接

`S/skill/` 实际有 40 个文件，含缓存文件，不是 40 个 Skill。六组为 Overlay 管理、DMA 缓冲、契约代码生成、参考比较、故障排查、提示词工作流。

建议保留现有 `pynq-overlay-preflight` 的已测范围，先审阅六组实现，按功能选择吸收或引用；不要仅拼目录宣称一个通用验证完备的工具包。

1. 逐项登记作者／来源、许可、输入、输出、副作用、失败条件及真实验证证据。
2. 修正示例导入与真实目录的关系：根 README 用 `skill.overlay_manager`，实物却是 `01_overlay_manager` 等编号目录；在最终副本确定可执行的包布局和调用方式，并实际跑示例。
3. <span style="color:#C00000">【待核验】README 中支持多板卡、Versal、多个 PYNQ/Python/内核版本的声明尚无对应跨平台实测矩阵，须改为目标范围与逐平台验证状态。</span>
4. 优先补离线负例：缺文件／哈希不符、HWH 解析失败、地址/宽度不匹配、ABI 不匹配，以及检查器执行前后输入不变。测试数不当作系统覆盖率。
5. 对 DMA 生命周期、缓存、超时清理做可控 mock 测试，再做板上验证。不能因为上下文管理器退出就认定 DMA 已停，也不能在仍有 PL 访问时释放 CMA。
6. 两类归档分开：通用可复用工具及验证；KV260/V24 专用配置、设备树和加载后端。无板环境不调用有副作用的 Overlay 加载器冒充只读检查。
