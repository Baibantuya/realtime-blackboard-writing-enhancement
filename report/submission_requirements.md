# Submission requirements and preparation

更新：2026-11-03。依据 AMD 赛题 3.3.3.1、3.3.3.2、3.3.3.3 与 3.3.5。官方条文的文字摘录见 [赛题摘录](ai_sessions/member_c/sources/rules/amd_section_3_3.txt)。

| 项目 | 赛题要求 | 本项目准备方式 |
|---|---|---|
| 开源及许可证 | 强烈要求在 GitHub 或 Gitee 开源，采用允许再分发的协议，推荐 MIT / Apache-2.0 | 用户已选择 MIT；根目录 `license.txt`。私有仓库用于整理，正式提交时公开并提供地址。第三方材料保留各自许可。 |
| AI 交互 | 提示词、模型回答与自我纠错轨迹 | 团队提供真实交互节选及对应工程结果；A/B 总结用于案例导读，C 已有可见消息摘录。无逐成员提交全部聊天的条款。 |
| 性能与正确性 | 仿真/验证、综合实现报告、实测输出与参考结果的对比 | 保存支撑报告关键数值的代表性原始报告、日志或 CSV，标明版本、条件和字段。无需全部历史日志。 |
| 真实样本 | 提交可复现工程和必要测试材料 | 测试平台、确定性生成输入、期望输出与比较脚本可支撑算法复测；实测输出按实际硬件版本提供。未要求整套课堂视频或训练数据集。 |
| 板测 | 作品板上跑通并提供实测输出 | 原 V24 实机证据保留。2025.2 C5 记录为待板测，现有 C5/R5 实现结果独立列出。 |
| 历史测试 | 当前工程应有可复现验证资料 | 使用本包当前测试与报告。旧 60+4 汇总单列历史记录，详见测试说明。 |
| 引用附件 | 完整工程及支撑技术结论的材料 | 报告主要结论对应附件见证据索引；历史工作区超链接按来源追溯，旧版本和暂缓功能的附件按相关性选取。 |
| Skill | 可复用技能包与用法、来源、验证材料 | `skill/` 已收录原六模块、修订工具与离线检查。PYNQ 泛化效果按已验证范围描述。 |

## 团队 AI Sessions

一个代表案例可按“实际问题 → 真实提示词 → 模型可见回答 → 反馈与纠错 → 采纳的实现 → 测试证据”组织，引用现有消息文件。可脱敏、截取关键轮次，并注明节选。A/B 无需为了成员覆盖而导出全部聊天；报告中若使用某次 A/B 对话的具体纠错故事，补该案例的关键原文即可。不要把事后总结标成逐字原始聊天。

## 旧版 60+4 的具体含义

旧冻结包 `validation/test_summary.json` 中有四个字段：主机回归 60 项、主机 tri-fixes 4 项、ARM 回归 60 项（含 Native C Q）、ARM tri-fixes 4 项。该 JSON 为结果汇总；没有逐用例名称、输入、断言与原始执行日志。

旧 `source/ps/run_tests.py` 从同级 `legacy_tests/` 和 `tests/` 发现测试；冻结包的该目录只保留 `ps_runtime_v2/`，其中的两个测试文件与所需两个目录的组织不同。缺口是重跑这组历史计数所需的源码、依赖/参考模块、实际命令和日志。现有 RTL/HLS 目录中另有测试文件，不能仅按数量并成 60+4。

无需恢复全部旧版本。可采用当前源码对应的测试集合与结果，把旧 60+4 作为历史交付方汇总。若继续在报告中写“60+4 已复测”，则应补齐这组测试并重新运行。历史汇总原件见 [legacy_test_summary.json](attachments/legacy_test_summary.json)，原入口见 [legacy_run_tests.py.txt](attachments/legacy_run_tests.py.txt)。
