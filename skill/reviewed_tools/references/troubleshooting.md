# 有证据边界的排障表

原六组文档中的 Session 编号、数值和因果链尚未逐项关联原记录。以下将其作为排查方向，不称为本轮发生的故障。本轮实际复现的候选工具故障见 [失败记录](../../evidence/evidence/20261027/candidate_failures.json)。

| 现象/假设 | 先核查什么 | 结论边界 |
| --- | --- | --- |
| 首帧超时/Line Buffer Full | 同版日志、视频格式/步长、上游输入、下游反压、时钟复位连接及对应寄存器契约 | 仅报错不能证明复位亚稳态，更不能证明宽高被错误交换；需要波形/寄存器与控制实验 |
| 旧帧/噪点 | 帧序号、缓冲所有权、输入flush、完成条件、输出invalidate | 不能仅因一次invalidate后不同就排除并发、覆盖和地址问题 |
| CMA分配失败 | 分配次数、缓冲寿命、CMA与内核记录、失败尺寸 | 内存不足、碎片、泄漏均需证据；池化不能保证永不失败 |
| Overlay/configfs失败 | 同版bit/HWH/DTBO、实际后端/驱动、占用进程、状态文件与日志 | 自动清状态/卸载Full可能破坏正在运行的系统；先明确授权对象与停稳流程 |
| 停止挂起/D状态 | 哪个调用不返回、内核堆栈和DMA所有权 | Python轮询超时无法中断阻塞MMIO；不自动kill、freebuffer或重载 |
| 地址截断/Bus Error | 实际物理地址、IP的m_axi_addr64配置、HWH及头文件的每个指针宽度 | 同一KV260中Scene为32位、Restore为64位，不能按CPU位数统一处理 |
| FPS低 | 采集/有效内容更新/呈现独立计数；同一单调时钟的阶段耗时与窗口 | 阶段耗时不是端到端，PC耗时不能代替ARM实测；先定位再优化 |
