# 校正核 C/RTL 联仿增量

2026-10-29。`src/board_rectify_rgb.cpp` 和 `rgb565.h` 从 R5 原样复制，算法与综合配置未改动；新增内容仅为测试入口及运行脚本。工具为 Vitis HLS / XSim 2025.2，K26、5 ns。

本轮结果以 `review.json` 为准；复查脚本为上级 `audit_rectify.py`。

| 测试 | 覆盖 | 状态 |
|---|---|---|
| `small.tcl` | 20 组 32×24 变换／二值／通道顺序组合，另加 16×3 缓存行边界；63 次调用 | C/RTL 通过 |
| `boundary.tcl` | 1920×3 最大宽度、16×1080 最大高度；4 组场景、12 次调用 | C/RTL 通过 |
| `full.tcl` | 两组 1920×1080，原计划 6 次调用 | C 通过；RTL 初始化时内存耗尽，人工停止 |
| `single.tcl` | 一张 1920×1080 恒等映射，1 次调用 | C 通过；RTL 内存持续上涨，人工停止 |

小图和边界测试逐像素检查 RGB565 输出，还检查状态、角点元数据、诊断计数、复用源地址后的缓存刷新、无效几何输入和尾部哨兵。边界尺寸不是 1920×1080 整帧，也不能代表所有分辨率／变换的穷尽覆盖。原 C 测试的 20 组 1080p 结果保留，不能替代 RTL 联仿。

## 整帧试验限制

首次整帧 XSim 工作集达到约 20.5 GiB、系统仅余约 0.3 GiB 可用内存，已核对进程身份后停止。单次调用重试仍在相同初始化仿真时刻持续增长，停止时工作集约 15.8 GiB。工具均因此返回非零，保留 `full.log`、`single.log` 和对应 `*_resource_stop.json`，没有把中断改写成成功。

生成测试台的 `file_agent/mem_model.sv` 会先读取各次调用的数据并建立内存页；`file_read_agent.sv` 用队列读取二进制向量。波形记录已关闭，生成 Tcl 中 `log_wave` 为注释。多次调用预载是初步排查方向，但单次调用仍复现，故**不能认定单纯减少帧数已经解决根因**。尚需进一步隔离 XSim 与生成的 UVM 文件／内存模型的开销，或在资源充足且版本一致的环境复测；不要修改待测 RTL 来掩盖仿真环境问题。

<span style="color:#C00000">【未通过完整 1080p RTL 验证】两次资源中断没有得到像素一致性结果，既不能作为通过证据，也不能据此认定 RTL 算法错误。没有得出真实帧率、实机带宽或新位流画质结论。</span>

运行脚本使用原任务的 ASCII 短路径映射 `W:`，新目录已存在时会拒绝覆盖。重复验证应使用新的输出目录；不要删除原始失败证据后重跑。`p/` 为通过的小图工程，`boundary/` 为边界工程，`f/` 和 `oneframe/` 为保留的整帧失败现场。
